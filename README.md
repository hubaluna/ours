# ours.

Маленькі речі, які роблять життя разом простішим. Приватний PWA-простір для двох: покупки, бажання, секретні подарунки та плани. Інтерфейс українською, ціни у гривнях, дати за Europe/Kyiv.

Проєкт реалізовано на React + TypeScript strict + Vite + Tailwind CSS + Motion + Supabase. Немає власного сервера. Хостинг — GitHub Pages. Залежності зафіксовані у `package-lock.json` і `package.json`.

## Що вже працює

- Чотири вкладки, персональна головна, світла / темна / системна тема.
- Покупки: додавання, редагування, кількість, категорії, ціна, відмітка / повернення з Undo, підтвердження видалення, підказки попередніх товарів, групування.
- Завершення купленого списку як атомарної сесії, історія, повторення списку. Одночасні зміни серіалізуються сервером.
- Власні й партнерські бажання, фотографії, ціни, посилання, примітки, пріоритети, редагування своїх бажань.
- Секретне бронювання: «Заплановано» / «Придбано». Доступ обмежений автором на рівні PostgreSQL; власник бажання не має доступу до резервації.
- Календар: місяці, вибір дня, події на весь день, час, місце, категорія, редагування / видалення обома учасниками.
- Email/password, підтвердження пошти, незалежні сесії, створення простору, випадкові одноразові запрошення на 48 годин, максимум двоє учасників.
- Supabase Realtime, повторне завантаження після перепідключення, індикатори з’єднання, блокування повторного submit, повідомлення про помилки.
- Приватний Storage, зменшення зображень до 1400 px, WebP, обмеження типу / розміру, імена та аватари, JSON-експорт без бронювань.
- Скляна нижня навігація, shared layout-анімації, bottom sheets, захист незбережених форм, focus trap, Escape, safe area, адаптація до Visual Viewport, reduced motion / transparency.
- Manifest, PNG-іконки, Apple touch icon, service worker, запит перед оновленням. Кешується лише статична оболонка.
- Окремий позначений деморежим з локальним збереженням. Він не симулює синхронізацію й не звертається до приватної бази.

## Запуск без встановлення програм на ваш пристрій

Усе налаштування нижче можна виконати з Safari на iPhone. Команди розробника наведені окремо; запускати їх на телефоні не потрібно.

1. Створіть GitHub-репозиторій `ours` через [github.com/new](https://github.com/new). Для GitHub Pages на безкоштовному особистому тарифі зазвичай потрібен **public** репозиторій. Публічний frontend-код не надає доступу до приватних даних Supabase.
2. Надайте GitHub-інтеграції Codex доступ до нового репозиторію й передайте Codex його URL для перенесення готового проєкту. У цьому сеансі API відхилив створення репозиторію: `Resource not accessible by integration (createRepository)`. Жоден існуючий репозиторій не змінено.
3. Код має лежати в корені репозиторію, включно з `.github/workflows/pages.yml`, `package-lock.json`, `public/` та `supabase/`. Не завантажуйте ZIP як єдиний файл у репозиторій: GitHub не розпаковує його автоматично.
4. Створіть Supabase-проєкт і застосуйте дві SQL-міграції за інструкцією нижче.
5. Додайте дві публічні змінні GitHub Actions.
6. У GitHub → **Settings → Pages → Build and deployment → Source** виберіть **GitHub Actions**.
7. Відкрийте **Actions → Verify and publish ours. → Run workflow → main**. Наступні зміни в `main` збираються й публікуються автоматично. Pull request лише перевіряється, без публікації.
8. Адреса з’явиться в успішному deploy job та Settings → Pages. Для репозиторію `ours` очікуваний формат — `https://YOUR_LOGIN.github.io/ours/`. Це приклад, а не вже опублікований сайт.

## Supabase: точне підключення

### 1. Проєкт і база

1. На [supabase.com/dashboard](https://supabase.com/dashboard) створіть новий проєкт на Free-плані. Оберіть зручний європейський регіон. Пароль бази зберігайте у власному менеджері паролів.
2. Дочекайтеся готовності проєкту. Відкрийте **SQL Editor → New query**.
3. Скопіюйте весь вміст [`supabase/migrations/001_core.sql`](supabase/migrations/001_core.sql), натисніть **Run**.
4. В окремому запиті запустіть весь [`supabase/migrations/002_storage_realtime.sql`](supabase/migrations/002_storage_realtime.sql).
5. Міграції розраховані на одноразове застосування у цьому порядку. Не запускайте їх повторно поверх створеної схеми. Наступні зміни слід оформлювати новими міграціями.
6. Переконайтеся, що є 10 таблиць: `profiles`, `couples`, `couple_members`, `couple_invites`, `shopping_sessions`, `shopping_items`, `shopping_product_history`, `wishes`, `gift_reservations`, `events`. На всіх увімкнено RLS.

### 2. Authentication

1. У **Authentication → Sign In / Providers → Email** увімкніть Email/password і підтвердження email. Встановіть мінімальну довжину пароля не менше 10 символів.
2. У **Authentication → URL Configuration** задайте **Site URL** рівно з адресою Pages, наприклад `https://YOUR_LOGIN.github.io/ours/`.
3. Додайте цю ж адресу до **Redirect URLs**. Для розробки за потреби окремо додайте `http://localhost:5173/`. Не використовуйте широкі wildcard для довільних доменів.
4. Якщо вмикаєте власний SMTP, налаштуйте його в Supabase, а не у frontend. Вбудована пошта Supabase має обмеження отримувачів та частоти: перевірте актуальні обмеження у Dashboard. Для двох власних акаунтів можна додати обидві адреси до команди Supabase, якщо цього вимагає вбудований email-сервіс, або налаштувати підтримуваний SMTP.
5. Зареєструйте два акаунти та підтвердіть пошту. Після цього рекомендовано вимкнути **Allow new users to sign up**: вже створені акаунти продовжать входити. Приєднання існуючого другого акаунта за запрошенням продовжує працювати.

### 3. Storage і Realtime

Друга міграція вже:

- створює bucket `photos` з `public = false`, лімітом **5 МБ** і JPEG/PNG/WebP;
- дозволяє читання лише учасникам відповідного простору;
- дозволяє завантаження лише в `<couple_id>/<auth.uid()>/<random>.webp`;
- дозволяє видалення власних фотографій; перезапис файлів заборонено;
- додає спільні таблиці застосунку до `supabase_realtime`, виключаючи `gift_reservations`: навіть видалення секретного подарунка не має породжувати Realtime-сигнал. Автор перечитує свої бронювання після власної дії та при поверненні до застосунку.

Не робіть bucket публічним. Фото відкриваються через signed URL на 1 годину, який оновлюється, поки екран відкритий. У налаштуваннях публікації Supabase перевірте, що зазначені таблиці додані. Окремого Realtime-сервера запускати не потрібно.

### 4. Дві змінні GitHub Actions

У Supabase → **Project Settings → API / API Keys** скопіюйте Project URL та **publishable key** (`sb_publishable_…`) або legacy **anon key**.

У GitHub → **Settings → Secrets and variables → Actions → Variables** додайте:

| Назва                           | Значення                                         |
| ------------------------------- | ------------------------------------------------ |
| `VITE_SUPABASE_URL`             | `https://YOUR_PROJECT.supabase.co`               |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | publishable key або legacy anon key              |
| `VITE_BASE_PATH`                | необов’язково: `/ours/`; для власного домену `/` |

Workflow автоматично встановлює `base` як `/<назва-репозиторію>/`, якщо третя змінна відсутня. Для репозиторію `YOUR_LOGIN.github.io` також установіть `/`.

Ці дві Supabase-змінні **публічні за призначенням** і потрапляють у JavaScript збірки. Дані захищає RLS. **Не додавайте** `service_role`, `sb_secret_…`, пароль PostgreSQL, SMTP-паролі чи адміністративні токени до `VITE_*`, коду або Git.

Змінили змінні — запустіть workflow знову: вони підставляються під час збірки. Без обох змінних збірка явно працює в деморежимі.

## Підключення двох акаунтів

1. Перший користувач відкриває сайт, реєструється, підтверджує пошту й входить.
2. Натискає **«Створити простір»**.
3. Відкриває аватар → **«Створити запрошення»** → **«Копіювати»** й особисто передає посилання партнеру.
4. Другий користувач відкриває посилання на своєму телефоні, створює незалежний акаунт і підтверджує пошту. Для збереження запрошення повертайтеся у той самий браузер; інакше просто відкрийте вихідне запрошення ще раз.
5. Після входу код уже підставлений. Натискає **«Приєднатися»**. Не створюйте другий простір для цього акаунта.
6. Тепер обидва бачать спільні покупки, бажання й події. У просторі може бути лише двоє.
7. Посилання містить 244 біти випадковості (два UUID v4), живе 48 годин, зберігається в базі лише як SHA-256-хеш і використовується один раз. Нове запрошення анулює попереднє. Не передавайте його стороннім.

## Встановлення на iPhone та Android

**iPhone:** відкрийте опубліковану HTTPS-адресу в Safari → **Поширити** → **На початковий екран** → **Додати**. Запускайте через нову іконку. За потреби увійдіть ще раз: Safari та встановлена PWA можуть мати окреме сховище сесій.

**Android:** Chrome → меню → **Установити застосунок / Додати на головний екран**.

PWA працює у standalone-режимі, який підтримує ОС. Системний launch screen залежить від iOS / Android; іконки й background color налаштовані. Свіжа версія показує кнопку «Оновити». Завершіть введення у формі перед оновленням.

Без інтернету доступна кешована оболонка. Приватні дані не зберігаються service worker і після офлайн-перезапуску можуть бути недоступні. Немає черги офлайн-записів або прихованого відкладеного submit.

## Структура

```text
src/
  App.tsx                   оболонка, чотири вкладки, навігація
  components/
    ui.tsx                  кнопки, sheet, toast, avatar, skeleton, segmented
    Forms.tsx               форми покупок, бажань, подій
    ShoppingRow.tsx         чекбокс, pending, Undo, layout-перехід
    Illustrations.tsx       власні SVG-ілюстрації
  features/
    Home.tsx Shopping.tsx Wishes.tsx Plans.tsx
    Auth.tsx Settings.tsx
  hooks/
    AppContext.tsx          дані, сесія, mutations, Realtime, pending
    useTheme.ts useImage.ts
  lib/
    types.ts supabase.ts demo.ts utils.ts motion.ts
  styles.css                дизайн-токени, теми, адаптивність
public/                     PWA-іконки
supabase/migrations/        PostgreSQL, RLS, RPC, Storage, Realtime
tests/                     DOM та PostgreSQL-тести; e2e-сценарії
.github/workflows/pages.yml перевірка й публікація
```

Маршрутизатор не потрібен: чотири вкладки використовують локальний стан; єдиний URL завжди відкривається на GitHub Pages. Запрошення передаються через `#invite=…`, очищаються з адресного рядка й тимчасово зберігаються в sessionStorage. Refresh відкриває головну.

## Перевірки та розробка

Для Codex / GitHub Actions / Codespaces (на вашому iPhone нічого встановлювати не потрібно):

```sh
npm ci
npm run dev
npm run lint
npm test
npm run build
```

Для локального реального режиму скопіюйте `.env.example` у `.env` і заповніть лише публічні значення. `.env` і всі його приватні варіанти ігноруються Git.

Фактично виконані перевірки й обмеження описано в [`docs/VERIFICATION.md`](docs/VERIFICATION.md). Тести завжди ізольовані від реального `.env` і не звертаються до вашої бази. Наявність SQL-тестів не означає, що живий Supabase-проєкт уже підключений.

Браузерні тести підготовлені у `tests/e2e`. У середовищі з дозволеним браузером: `npx playwright install chromium`, потім `npm run test:e2e`. Вони перевіряють мобільний viewport, 320 px, навігацію, sheet, чекбокси та темну тему й зберігають скриншоти. У цьому сеансі ці тести **не запускалися**.

## Поточні обмеження

- Потрібні ваш Supabase-проєкт, застосування міграцій, email-налаштування та дві публічні змінні. Немає живої перевірки Auth / Storage HTTP / Realtime на двох пристроях без них.
- Публікацію заблоковано відсутністю дозволу GitHub створювати репозиторій. Сайт не опублікований.
- Візуальні скриншоти, фізична клавіатура iPhone, плавність 60 FPS і реальне встановлення на iOS у цьому сеансі не перевірялися.
- Немає push-нагадувань, повторюваних подій, зовнішніх календарів чи офлайн-синхронізації.
- Одночасне редагування одного поля використовує останній успішний запис. Архівація покупок і приєднання до пари транзакційні.
- Завантажуються JPEG / PNG / WebP, вихідний файл до 12 МБ. HEIC слід конвертувати через Photos або вибрати сумісне фото. Оригінали та EXIF не зберігаються.
- Фото, завантажене перед скасуванням форми чи замінене іншим, може залишитися в приватному bucket. Автоматичного очищення сиріт немає. Для двох людей стежте за квотою Storage; видаляйте лише файли, які не використовуються в `profiles.avatar_path` чи `wishes.image_path`.
- JSON-експорт містить спільні покупки / історію / бажання / події, без бронювань та бінарних фотографій.
- Демодані містяться лише в localStorage цього браузера; це не місце для приватних даних. Очищення даних браузера видаляє їх. Якщо квота заповнена, нові демозміни залишаються лише в пам’яті до закриття сторінки.
- Немає інтерфейсу розриву пари, видалення акаунта або перенесення в іншу пару. Перший реліз розрахований на один постійний простір для двох.
- Supabase Free може призупиняти неактивні проєкти й обмежувати надсилання пошти. Слідкуйте за повідомленнями Dashboard. Повної наскрізної криптографії немає: захист — Auth, RLS, HTTPS і приватний Storage.
