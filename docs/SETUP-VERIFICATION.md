# Перевірка автоматичного налаштування Supabase

## Живе підключення — 11 листопада 2026 року

Поточне середовище має обидві публічні змінні та адміністративний токен Supabase. GitHub підтвердив читання та право push у `hubaluna/ours`; Pages використовує GitHub Actions. Читання Actions Variables повертає 403, тому frontend отримує перевірені публічні параметри з `src/lib/public-config.json`. Адміністративний токен у файли або збірку не записувався.

- `npm run setup:supabase` через Management API підтвердив порожню схему. Тільки після цього застосовано захищений `--apply`: усі міграції 001–003, 14 таблиць із RLS, приватний bucket `photos`, виключення `gift_reservations` із Realtime.
- `link-preview` розгорнуто через Management API з `verify_jwt=false`; перевірка користувача, членства й бюджету виконується всередині функції. Живе читання метаданих фільму, бажання та рецепта успішне. Неавторизоване членство та локальний URL відхиляються.
- Тимчасові підтверджені акаунти перевірили незалежний вхід за паролем, створення простору, одноразове запрошення другого учасника, відмову третьому, RLS для стороннього акаунта, Realtime, приватний upload/signed download та секретне бронювання без видимих отримувачу записів чи новин.
- Дві незалежні браузерні сесії увійшли в production-збірку; створена покупка з’явилась у партнера без перезавантаження. Тимчасові акаунти, простір і фото видалено після перевірки.
- ESLint, 82 тести, TypeScript/Vite/PWA build, перевірка base `/ours/` і відсутності кешування Supabase API — успішні. Deno typecheck модульної та Dashboard-функцій — успішний.
- 14 браузерних сценаріїв пройшли у Chromium і WebKit: шість вкладок, покупки/кіно/календар, імпорт тексту, теми та viewport 320×568, 390×664, 390×844, 844×390, 1280×800. Переглянуто скриншоти компактних покупок.

**Що ще потрібно власнику:** Management API читання й зміни Auth Config повертають HTTP 403. Email/password та підтвердження email ввімкнені (перевірено через публічні Auth settings), але Site URL, redirect allowlist, мінімальну серверну довжину пароля й SMTP змінити/перевірити цим токеном не вдалося. Встановіть Site URL і Redirect URL `https://hubaluna.github.io/ours/`, мінімальний пароль 10 символів. Далі перевірте отримання листів двома власними адресами; вбудована пошта Supabase може потребувати власного SMTP. Тестові акаунти було підтверджено адміністративно без надсилання листів — ці перевірки не підтверджують доставлення пошти.

## Попередня перевірка команди налаштування

Перевірено в задачі 11 листопада 2026 року:

- ESLint — без помилок.
- 78 автоматичних тестів пройшли; 7 нових сценаріїв перевіряють безпечне налаштування Supabase через замоканий Management API.
- Production-збірка TypeScript/Vite/PWA — успішна.
- PostgreSQL-тест виконує весь setup у транзакції з блокуванням; повторний запуск відхиляється, 14 наявних таблиць зберігаються.
- `npm run setup:supabase` у поточній задачі завершився з явною помилкою `SUPABASE_ACCESS_TOKEN is missing in this task`, без мережевого запиту й без змін бази або публічного конфігу.

Нова команда перевіряє відсутність токена/прав, режим лише читання за замовчуванням, відмову працювати поверх наявних таблиць, транзакційний guard, відбір публічного ключа й відсутність запису конфігу після помилок. Відповіді помилок API не виводяться, редиректи заборонені. Нові тестові ключі й відповіді синтетичні.

Живий Supabase, дві реальні сесії, доставлення листів, завантаження фото та HTTP Realtime не перевірялися: у прикріпленому до цієї задачі середовищі немає токена чи публічного підключення. Ця перевірка не підтверджує стан опублікованого користувачем середовища `ours` — поточна задача до нього не прив'язана.

Браузерні тести для цього оновлення локально повторно не запускалися: змінено лише команду налаштування, тести та документацію; UI не змінювався. Попередні браузерні результати наведено окремо у [VERIFICATION.md](VERIFICATION.md).
