# ours. — запуск із телефона

Код зберігається в [hubaluna/ours](https://github.com/hubaluna/ours). Встановлювати програми або писати код на телефоні не потрібно.

**Сайт опублікований:** [https://hubaluna.github.io/ours/](https://hubaluna.github.io/ours/). Код у `main`, 24 автоматичні тести та 4 браузерні перевірки пройшли, deploy успішний. Сайт, ресурси, іконки, manifest і service worker перевірені через HTTPS (HTTP 200). [Скриншоти](PREVIEW.md).

До підключення Supabase сайт працює у **позначеному деморежимі**. Демодані не синхронізуються між пристроями й не є вашою приватною базою.

## 1. GitHub Pages — уже готово

Репозиторій публічний за рішенням власника. У Pages вже вибрано **Source → GitHub Actions**. Усі наступні зміни коду проходять перевірки й публікуються автоматично. Додаткових дій у налаштуваннях Pages зараз не потрібно.

Приватність коду й приватність даних — окремі речі: особисті дані зберігатимуться в захищеній базі Supabase після її підключення.

## 2. Supabase — один запит

1. Відкрийте [Supabase](https://supabase.com/dashboard) та створіть безкоштовний проєкт. Якщо проєкт уже є, використовуйте **новий або порожній**: налаштування створює таблиці застосунку.
2. У репозиторії відкрийте [supabase/setup.sql](https://github.com/hubaluna/ours/blob/main/supabase/setup.sql), натисніть кнопку копіювання вмісту файлу.
3. У Supabase відкрийте **SQL Editor → New query**, вставте скопійований текст і натисніть **Run**. Це один атомарний запит для бази, RLS, запрошень, фотографій і Realtime. Запускати лише один раз. Замість нього можна застосувати дві міграції з README; **не виконуйте обидва варіанти**.
4. У **Authentication → URL Configuration** додайте адресу вашого сайту до **Site URL** і **Redirect URLs**. Для Pages це `https://hubaluna.github.io/ours/`.
5. У **Authentication → Email** увімкніть email/password, підтвердження адреси та мінімальну довжину пароля 10 символів. Якщо листи не надходять, перевірте обмеження вбудованої пошти в Dashboard — див. README.

## 3. Два публічні значення

У Supabase → **Project Settings → API / API Keys** потрібні тільки:

- **Project URL** — виглядає як `https://xxxxxxxx.supabase.co`;
- **publishable key** — починається з `sb_publishable_` (або старий `anon` key).

Це публічні клієнтські значення. Їх можна передати Codex для підключення: він запише ці публічні значення у конфігурацію й перебудує сайт, без ручного заповнення GitHub Variables. **Не передавайте** пароль бази, `service_role`, `sb_secret_…` чи адміністративний access token.

Альтернативно додайте значення самостійно в [Actions Variables](https://github.com/hubaluna/ours/settings/variables/actions):

| Назва                           | Значення                   |
| ------------------------------- | -------------------------- |
| `VITE_SUPABASE_URL`             | ваш Project URL            |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | ваш publishable / anon key |

Якщо налаштовували Variables самостійно, запустіть [workflow](https://github.com/hubaluna/ours/actions) знову. До підключення працює чітко позначений деморежим.

## Далі — уже у застосунку

Перший користувач реєструється, підтверджує email, створює простір і в налаштуваннях генерує запрошення. Другий відкриває його, входить своїм акаунтом і натискає «Приєднатися». Після створення обох акаунтів можна вимкнути нові реєстрації в Supabase.

На iPhone: **Safari → Поширити → На початковий екран**. У встановленій PWA може знадобитися окремий вхід.
