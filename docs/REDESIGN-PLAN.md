# ours. 2 — план реалізації до початку змін

## Мета

П’ять вкладок, один компактний основний екран на кожну. Дані не обрізаються без можливості розгорнути їх. Головна — лише непрочитані зміни партнера. Інтерфейс залишається українським, приватним і придатним до встановлення на iPhone.

## 1. Контракт компонування

- AppShell займає 100dvh з safe area; документ не прокручується в авторизованому застосунку.
- Заголовок і навігація мають власні зарезервовані області. Контент не заходить під них.
- Кількість рядків визначається доступною висотою через ResizeObserver. Перехід між сторінками кнопками, без прихованого вертикального скролу списків.
- Довгі назви мають короткий огляд і повний текст у detail sheet. Форми й розгорнуті панелі можуть прокручуватися: це явна дія користувача, а не довга головна сторінка.
- Календар компактний; на низькому landscape-екрані повний місяць розгортається окремо.
- Мінімальна перевірка: 320×568, 390×664, 390×844, 844×390, desktop. Збільшений текст не має закривати кнопки або робити дані недоступними.

## 2. Дані та приватність

- movies: спільні фільми, URL джерела / постера, назва, рік, жанри, опис, статус «хочемо / переглянули», автор.
- activity_events: тільки дозволені спільні зміни shopping/wishes/movies/events; автор, тип, ID сутності, короткий заголовок.
- activity_reads: user_id + activity_id; кожен відмічає лише власні перегляди. Власні зміни не показуються як новини партнера.
- Переглянуте позначається після явного відкриття повідомлення або кнопки «Усе переглянуто». Сам факт появи на екрані не списує повідомлення.
- gift_reservations виключена з тригерів активності та Realtime-публікації.
- Нова SQL-міграція для наявних проєктів; згенерований setup.sql для нових. RLS та обмежені права UPDATE на всіх нових таблицях.
- Імпорт інгредієнтів — одна атомарна RPC-операція, не частково збережений набір запитів.

## 3. Імпорт посилань

- Спільний parser для Open Graph, schema.org JSON-LD (Movie, VideoObject, Product, Recipe) та title/description.
- Serverless Supabase Edge Function: перевірка JWT та членства у парі, дозволений origin, ліміти частоти, часу й розміру відповіді; тільки HTTPS.
- Захист SSRF: IP literal, локальні / приватні / link-local адреси, localhost та службові адреси заборонені; DNS-перевірка кожного hostname і кожного redirect. URL credentials, довільні порти та необмежені redirects заборонені.
- HTML не виконується і не вставляється через dangerouslySetInnerHTML. Витягуються тільки текстові поля й перевірені HTTPS-посилання. Короткі витяги, без збереження всієї сторінки.
- YouTube/Vimeo: лише явні відомості oEmbed / сторінки. Рік та жанр не вгадуються за назвою трейлера.
- Попередній перегляд з редагуванням обов’язковий. Recipe ingredients можна вибрати перед додаванням; дроби, одиниці та нерозпізнаний текст зберігаються зрозуміло.
- У demo та без розгорнутої Edge Function: чесний резервний шлях вставити текст/HTML або заповнити вручну. Не використовувати сторонні відкриті CORS-проксі для приватних посилань.
- Зовнішня залежність: реальний Supabase ще не підключений; код функції, SQL та інструкції готуються без адміністративних ключів.

## 4. Дизайн

- Офіційна e-Ukraine з джерела Мінцифри; локальне розміщення, font-display: swap, ліцензія/атрибуція.
- Ієрархія 26–30 px для заголовків, 14–16 px для основного тексту, без великих декоративних hero на кожній вкладці.
- Палітра тепла біла / шавлія; темна — графітова зелень. Молочне матове скло лише на навігації, меню і sheets; непрозорий fallback.
- Рослина й саморобні SVG-ілюстрації прибираються. Нова графіка генерується спеціально для ours.; іконки залишаються Lucide.
- Motion: спільний індикатор п’яти вкладок, короткі fade/layout-переходи, reduced motion. Увага до читабельності скла, а не максимальної прозорості.

## 5. Порядок виконання

1. Дизайн-активи й шрифт; типи та parser із тестами.
2. Міграція movies/activity/reads та атомарних покупок, тести PostgreSQL.
3. Edge Function та тести URL/SSRF/redirect/size/rate/auth; документація підключення.
4. Data provider: нові таблиці, Realtime, receipts, demo migration без втрати попередніх демоданих.
5. Нова оболонка, pagination/detail/import UI, п’ять вкладок, нова головна.
6. Локальні TypeScript/ESLint/DOM/SQL тести; production PWA build.
7. GitHub WebKit/Chromium: функції, viewport, відсутність scroll/overflow, screenshots, visual review.
8. Виправлення фактичних проблем, публікація й HTTP-перевірка Pages. Повідомити окремо про те, що потребує налаштування Supabase.

## Критерії приймання

П’ять справних вкладок. Вертикального scroll документа немає на узгоджених viewport; довгі дані доступні через pagination/sheets. Прочитані новини не повертаються після refresh. Подарунки не створюють видимих отримувачу сигналів. Результат парсингу редагується, поля не вигадуються, приватні URL не обходять SSRF-захист. Старі покупки/бажання/події збережені. Збірка та фактично запущені тести проходять. Документація точно відрізняє працюючий demo, підготовлений backend і підключену інфраструктуру.

## Доповнення власника під час реалізації

Додано шосту вкладку «Меню» між Покупками й Кіно. Поки власний каталог ще не визначено, реалізується локальний генератор вечері з трьох частин: гарнір, м’ясо/риба, салат. Початковий набір позначено явно; немає вигаданого імпорту інгредієнтів чи кнопок збереження спільного меню без відповідних даних. Комбінація зберігається локально для користувача; це ідея, а не синхронізований план харчування. Перевірка viewport та навігації поширюється на всі шість вкладок.
