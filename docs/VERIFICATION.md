# Перевірка релізу

Дата: 10 листопада 2026.

## Фактично виконано

- `npm run build`: TypeScript strict і Vite production build успішні, service worker та manifest згенеровані.
- `npm run lint`: без помилок.
- `npm test`: 24 перевірки успішні.
- `npm audit --omit=dev --audit-level=high`: 0 відомих вразливостей production-залежностей на момент перевірки.
- Збірку для project path `/ours/` додатково перевірено на відносні ресурси, manifest scope / start_url та реєстрацію service worker.

## 6 DOM-інтеграційних перевірок

React Testing Library + user-event + jsdom, реальні компоненти й демосховище. Тільки PWA-реєстрацію підмінено, оскільки jsdom не має service worker.

1. Додавання покупки, відмітка, повернення, збереження у localStorage.
2. Додавання бажання та відкриття редагування.
3. Створення події на весь день.
4. Темна / світла тема й збереження вибору.
5. Попередження при закритті форми; назва й кількість не губляться після «Продовжити».
6. Бронювання партнерського бажання без додавання статусу в wish.

## 17 перевірок PostgreSQL / RLS

PGlite запускає обидві міграції; тест працює під реальними PostgreSQL-ролями. Обгортки Supabase Auth та Storage створено як тестові schema/table, publication присутня; мережевий Realtime не емулюється.

Перевірено створення пари, приєднання другого, відмову третьому, одноразовість / прострочення / заміну запрошення, заборону підробки членства, спільні покупки й події, архівацію / історію / повторення, заборону власних резервацій, доступ лише автору бронювання, неможливість змінити його автора, приховування від отримувача, ізоляцію іншої пари, захист профілю / чужих бажань, приватність фото й папки завантаження, заборону anonymous-доступу й відсутність секретних бронювань у Realtime-публікації.

## Один SQL-запит із телефона

Додатковий тест `tests/setup.test.ts` успішно застосував об’єднаний `supabase/setup.sql` до свіжого PostgreSQL-оточення: 10 таблиць, RLS на всіх таблицях і приватний bucket фотографій. Це альтернатива послідовному запуску двох міграцій, а не додаткова міграція поверх них.

## Що не запускалося

- Playwright / візуальні скриншоти: у сеансі немає доступного інструмента керування керованим браузером (`cua_repl.js`). Згідно з інструкціями середовища preview-сервер та альтернативне керування браузером не запускалися. Сценарії збережено в `tests/e2e` для доступного браузерного середовища.
- Фізичний iPhone, Safari keyboard, standalone-встановлення, оцінка FPS, фактичний WCAG-контраст у браузері.
- Реальна реєстрація email / SMTP, HTTP Storage, Realtime на двох телефонах: потрібен ваш Supabase.
- Репозиторій створено власником: `hubaluna/ours`. Доступ до налаштувань Pages / Actions API повертає HTTP 403; стан публікації дивіться у `docs/START-HERE.md`.
- Паралельний стрес-тест двох окремих PostgreSQL-з’єднань. Row locks та транзакційні обмеження реалізовано, але PGlite-тести виконуються послідовно.

## Приймальна перевірка після підключення Supabase

1. На двох пристроях увійти незалежними акаунтами, створити простір і прийняти запрошення.
2. А додає товар; Б бачить його без refresh. Б відмічає; А бачить оновлення. Видалення також зникає у партнера.
3. А додає бажання. Б бронює / позначає придбаним. А не бачить статусу; прямий SELECT `gift_reservations` з JWT А повертає порожній результат.
4. Третій акаунт не приймає використане запрошення і не читає чужі couple_id / wish_id / фото.
5. Подія створюється / редагується обома й відображається на головній.
6. Вимкнути мережу: індикатор змінюється, незбережений запис не видається за успішний. Увімкнути мережу: дані перечитуються.
7. Установити PWA на iPhone, перевірити клавіатуру, 320 px, збільшений текст, reduced motion і темну тему.
8. Перевірити JSON: покупки / бажання / події присутні, бронювань немає.
