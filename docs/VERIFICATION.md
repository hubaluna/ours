Успішний прогін оновлення: [GitHub Actions 42882139820](https://github.com/hubaluna/ours/actions/runs/42882139820), код `5d1ce45`.

- **build: success** — чисте встановлення залежностей, ESLint, 70 тестів, Deno typecheck, production-збірка для Pages і перевірка service worker.
- **browser: success** — **14 Playwright-перевірок**: WebKit з емуляцією iPhone 13 та desktop Chromium.
- **deploy: success** — застосунок опублікований: **https://hubaluna.github.io/ours/**.

Після deployment через HTTPS отримано HTTP 200 для HTML, усіх ресурсів із HTML, обох e-Ukraine WOFF2, нової графіки, іконок, manifest і service worker. У публічному CSS перевірено нове оформлення списків та правильний шлях `/ours/fonts/`; manifest має scope / start_url `/ours/` і display `standalone`.

Браузерні сценарії перевіряють усі шість вкладок, збереження переглянутих оновлень після reload, додавання / купівлю / повернення товару, генератор меню, додавання й перегляд кіно, форми, події, темну тему, імпорт тексту рецепта та відсутність необроблених JavaScript-помилок у головному сценарії.

На розмірах **320×568, 390×664, 390×844, 844×390 і 1280×800** перевірено всі шість вкладок: основний документ не має горизонтальної або вертикальної прокрутки; контент не перекриває навігацію, навігація в межах viewport. Додаткова перевірка підтверджує, що рядки поточної сторінки не обрізаються контейнером. Довгі списки доступні через сторінки. Форми, деталі та збільшений календар відкриваються окремо й можуть прокручуватися.

Browser-job використовує `--mode test`: він ізольований від живої бази навіть після заповнення публічної конфігурації. [Справжні скриншоти](PREVIEW.md) зберігаються як артефакт GitHub Actions та переглядаються візуально.

## Що не запускалося

- Фізичний iPhone, системна клавіатура Safari, standalone-встановлення, вимірювання FPS і повний аудит WCAG-контрасту.
- Реальна реєстрація email / SMTP, HTTP Storage, Realtime на двох телефонах, hosted Edge Function та читання зовнішніх URL: потрібен ваш Supabase.
- Паралельний стрес-тест двох окремих PostgreSQL-з’єднань. Row locks та транзакційні обмеження реалізовано; PGlite-тести послідовні.

## Приймальна перевірка після підключення Supabase

1. На двох пристроях увійти незалежними акаунтами, створити простір і прийняти одноразове запрошення. Третій акаунт не може приєднатися або читати дані.
2. А додає товар; Б бачить його без refresh. Б відмічає; А бачить зміну.
3. Б бачить нове оновлення від А на головній, відкриває його; після reload воно не повертається. У А власна дія у стрічці відсутня.
4. А додає бажання. Б бронює й позначає придбаним. А не бачить статусу або оновлення; прямий SELECT `gift_reservations` з JWT А повертає порожній результат.
5. Перевірити спільне кіно, редагування подій і JSON-експорт: покупки / бажання / кіно / події присутні, бронювань немає.
6. Розгорнути `link-preview`, перевірити рецепт / товар / трейлер; перед збереженням звірити знайдені поля. Джерело без метаданих має показати можливість ручного введення.
7. Вимкнути мережу: індикатор змінюється, незбережена зміна не видається за синхронізовану. Після перепідключення дані перечитуються.
8. Установити PWA на iPhone, перевірити клавіатуру, збільшений текст, reduced motion, темну тему та кнопку «Оновити».
